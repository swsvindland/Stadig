**Known gaps**

- The Watch doesn't recover an interrupted HealthKit workout. After a relaunch it starts a new one with the same sync id.
- A Watch session records as a single strength workout, conditioning included.
- A session run from the Watch saves its workout to Health even with Save to Health off: the phone's context (`PhoneContext`) doesn't carry the setting.
- The Watch's saved session isn't fully safe across an app update: `PhoneContext` and the `Gym` inside it still decode strictly, so a new required field would set a running session aside.
- A workout imported from Health and later deleted in the Health app stays in Stadig Lift. Whether to mirror those deletes is undecided.
- Progress photos saved before the quality pass stay large in the store and in sync (they were drawn at three times screen scale). New ones are stored at 1,400 px, and every photo displays downsampled.
- An assessment counts as complete only after its last day, or through "you can finish early". The final-week rule asks for more sessions than are scheduled, and its threshold is undecided.
- A typed body fat carries forward with no age limit, so a reading from months ago still beats this week's tape estimate and reaches Stadig Macro.
- Stadig Macro's onboarding allows 0 training days and publishes that to the shared profile, outside the shared range of 1 to 7.
- A weigh-in deleted in Health before a device's first read of changes stays in Stadig Macro, since a first read reports no deletions.
- A Stadig Macro phase ended partway through a week keeps that end in a new field. An older build on another device drops the field if it saves the plan again, and the phase then runs to its whole weeks, overlapping the diet break or mini-cut after it by up to 6 days.
- A Stadig Mind session saved by a newer version with an unknown purpose or attempt kind can't be read by an older one. Unknown courses are left out.
- Stadig Mind's "Read my handwriting" takes the strokes it read off the page by count. If any were erased while it was reading, that many strokes written meanwhile go too.
- Activities, weigh-ins, and Stadig Mind's sessions, test results and writing take their day from the phone's current time zone. Only Stadig Lift's sessions keep the zone they were logged in.
- The UI test plans retry a failed test once (`retryOnFailure`, at most 2 runs), so a flaky test could pass unnoticed.
- A few app tests read the real clock: two of Stadig Macro's model tests, and two of Stadig Mind's UI tests (one fails if a run crosses midnight, the other takes a different path on a rest day).
- On an iPad a SwiftUI `Table`'s first section header doesn't show (it looks to be under the column headers, and isn't in the accessibility tree either), so Stadig Lift's Program doesn't name its first day and Stadig Macro's Today doesn't head its first moment (later ones show). Seen on the simulator, not worked around.
- Lint is clean with this Mac's swift-format; CI's runs the same command.
